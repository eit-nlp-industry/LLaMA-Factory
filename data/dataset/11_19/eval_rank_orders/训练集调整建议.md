# 参数预测失败问题分析与训练集调整建议

## 一、问题总结

### 核心问题
模型在预测工具参数时，**无法推断隐式默认值参数**。这些参数在用户查询中未明确提及，但在工具schema中定义了默认值，训练数据中需要显式标注。

### 缺失参数统计（index 41-53，共11个案例）
- `group_by`: 11次全部缺失，目标值都是 `"status"`
- `status_filter`: 9次缺失，目标值都是 `"all"`
- `time_scope`: 7次缺失，目标值都是 `"current_month"`
- `include_trends`: 7次缺失，目标值都是 `false`

### 问题特征
1. **用户查询特征**：只提到景区名称、监控类型、阈值等显式信息
2. **目标参数特征**：包含大量隐式参数（默认值参数）
3. **预测结果**：模型只提取了显式参数，忽略了隐式参数

---

## 二、根因分析

### 1. 训练数据标注方式问题
- ✅ 训练数据中这些参数是**显式标注**的
- ❌ 但用户查询中**没有明确提到**这些参数
- ❌ 模型没有学会从工具schema的`default`值推断参数

### 2. 模型学习问题
模型需要学会：
1. 识别哪些参数有默认值（从工具schema中）
2. 根据查询上下文判断是否应该使用默认值
3. 即使查询中未提及，也要填充这些参数

### 3. 工具Schema信息
从工具schema可以看到：
```json
{
  "status_filter": {
    "default": "all",
    "enum": ["executing", "cancelled", "completed", "all"]
  },
  "time_scope": {
    "default": "current_month",
    "enum": ["current_month", "real_time", "specific_period"]
  },
  "include_trends": {
    "default": false
  },
  "group_by": {
    "default": "status",
    "enum": ["resort", "status", "time_period"]
  }
}
```

## 三、训练集调整思路

### 策略1：增加显式提示的训练样本（推荐）

**思路**：在训练数据中增加一些样本，在用户查询中**显式提到**这些参数，让模型理解这些参数的重要性。

**示例调整**：

**原查询**：
```
"检查一下大慈岩景区的运营状态是否出现异常，设置阈值为30"
```

**调整方案A - 显式提示**：
```
"检查一下大慈岩景区的运营状态是否出现异常，设置阈值为30，查看所有状态的订单，按状态分组，统计本月数据"
```

**调整方案B - 部分显式**：
```
"检查一下大慈岩景区的运营状态是否出现异常，设置阈值为30，需要查看所有状态"
```

**调整方案C - 自然语言表达**：
```
"检查一下大慈岩景区的运营状态是否出现异常，设置阈值为30，帮我看看各种状态的分布情况"
```

### 策略2：增加负样本训练

**思路**：增加一些样本，明确说明**不需要**某些参数，让模型理解何时应该使用默认值。

**示例**：
```
用户: "检查一下大慈岩景区的运营状态，只看异常情况，设置阈值为30"
目标: {
  "status_filter": "anomaly",  // 不是默认值"all"
  "time_scope": "current_month",
  "include_trends": false,
  "group_by": "status"
}
```

### 策略3：增加上下文推理样本

**思路**：增加一些需要从上下文推断参数的样本。

**示例**：
```
用户: "检查一下大慈岩景区的运营状态是否出现异常，设置阈值为30"
上下文: "用户想要查看运营状态异常情况，通常需要查看所有状态的分布，按状态分组便于分析"
目标: {
  "status_filter": "all",  // 从"异常情况"推断需要看所有状态
  "group_by": "status"     // 从"分布"推断需要按状态分组
}
```

### 策略4：增加工具Schema说明的训练样本

**思路**：在训练数据中增加对工具schema中default值的说明，让模型理解默认值的含义。

**示例调整**：
在训练数据的system prompt或工具描述中增加：
```
注意：以下参数有默认值，即使查询中未明确提及，也应该使用默认值：
- status_filter: 默认值为"all"，表示查看所有状态
- time_scope: 默认值为"current_month"，表示查看本月数据
- include_trends: 默认值为false，表示不包含趋势
- group_by: 默认值为"status"，表示按状态分组
```

### 策略5：数据增强 - 参数组合变化

**思路**：对现有训练样本进行数据增强，生成不同参数组合的变体。

**示例**：
```
原样本: 查询 + 完整参数（包含所有默认值）
变体1: 查询 + 缺少status_filter（让模型推断）
变体2: 查询 + 缺少time_scope（让模型推断）
变体3: 查询 + 缺少include_trends（让模型推断）
变体4: 查询 + 缺少group_by（让模型推断）
```

### 策略6：增加few-shot示例

**思路**：在训练数据中增加few-shot示例，展示如何从查询推断默认值参数。

**示例格式**：
```
示例1:
查询: "检查运营状态，设置阈值为30"
参数: {
  "monitoring_type": "operational_status",
  "alert_threshold": 30,
  "status_filter": "all",      // 默认值：查询中未提到状态，使用默认值"all"
  "time_scope": "current_month", // 默认值：查询中未提到时间，使用默认值"current_month"
  "include_trends": false,      // 默认值：查询中未提到趋势，使用默认值false
  "group_by": "status"          // 默认值：查询中未提到分组，使用默认值"status"
}

示例2:
查询: "检查运营状态，设置阈值为30，查看趋势"
参数: {
  "monitoring_type": "operational_status",
  "alert_threshold": 30,
  "include_trends": true,       // 显式提到"趋势"，使用true
  "status_filter": "all",       // 默认值
  "time_scope": "current_month", // 默认值
  "group_by": "status"          // 默认值
}
```

## 四、具体实施建议

### 优先级1：策略1 + 策略6（推荐组合）

1. **修改现有训练样本**（20-30%的样本）：
   - 在用户查询中自然融入参数提示
   - 保持目标参数不变
   - 让模型看到参数与查询的对应关系

2. **增加few-shot示例**：
   - 在训练数据开头增加3-5个示例
   - 展示默认值参数的使用规则
   - 说明何时使用默认值，何时不使用

### 优先级2：策略4（增强工具描述）

在工具schema描述中明确说明默认值的使用规则，让模型在推理时能够参考。

### 优先级3：策略5（数据增强）

对现有样本进行数据增强，生成参数缺失的变体，让模型学习推断。

## 六、评估指标

调整训练集后，重点关注以下指标：
1. **arg_match**：参数匹配率是否提升
2. **缺失参数数量**：group_by、status_filter、time_scope、include_trends的缺失率
3. **默认值参数填充率**：模型是否正确填充了默认值参数

---

## 七、总结

核心问题是**模型没有学会推断隐式默认值参数**。建议采用**策略1（显式提示）+ 策略6（few-shot示例）**的组合方式，在保持训练数据真实性的同时，让模型理解默认值参数的使用规则。

关键点：
1. 在部分查询中自然融入参数提示
2. 增加few-shot示例说明默认值规则
3. 保持目标参数标注的完整性
4. 让模型看到参数与查询的对应关系
