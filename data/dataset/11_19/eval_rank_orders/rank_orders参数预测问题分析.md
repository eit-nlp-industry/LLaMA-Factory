**总失败案例数**: 22个

## 二、详细问题分析

### 2.1 参数缺失问题

#### 问题1: `include_details` 缺失（8次）

**问题特征**：
- 预测值：`null`
- 目标值：`False` (6次) 或 `True` (2次)
- 用户查询中通常**没有明确提到**"详细信息"、"详情"等关键词

**示例**：
```
查询: "帮我查查2025年7月15日到8月15日大慈岩的订单金额排名前10"
目标: include_details = False
预测: include_details = null

查询: "我想知道大慈岩景区3月份哪些客户的订单总收入最高？"
目标: include_details = True  (查询中有"哪些客户"，暗示需要详情)
预测: include_details = null
```

**根因**：
- 查询中未明确提到"详细信息"、"详情"等关键词时，模型无法判断是否需要包含详情
- 需要从查询语义推断：查询"哪些客户"、"哪些订单"通常需要详情，而简单排名可能不需要

#### 问题2: `entity_type` 缺失（5次）

**问题特征**：
- 预测值：`null`
- 目标值：`customer` (2次) 或 `order` (3次)
- 用户查询中**有时明确提到**"客户"或"订单"，但模型未提取

**示例**：
```
查询: "帮我查一下2025年6月到8月期间，大慈岩景区客户下单数量最多的订单情况"
目标: entity_type = "customer"  (查询中提到"客户")
预测: entity_type = null

查询: "帮我查查2025年7月15日到8月15日大慈岩的订单金额排名前10"
目标: entity_type = "order"  (查询中提到"订单")
预测: entity_type = null
```

**根因**：
- 查询中虽然提到了"客户"或"订单"，但模型没有正确提取为`entity_type`参数
- 需要理解查询的语义：查询"客户下单"应该提取为`customer`，查询"订单排名"应该提取为`order`

#### 问题3: `resort_filter` 缺失（1次）

**问题特征**：
- 预测值：`null`
- 目标值：`"交运公司"`
- 查询中明确提到了景区名称，但模型未提取

**示例**：
```
查询: "2025年5-6月，交运公司客户下单数量最多的订单有哪些？"
目标: resort_filter = "交运公司"
预测: resort_filter = null
```

**根因**：
- 可能是实体识别问题，"交运公司"可能被识别为其他实体类型而非景区

### 2.2 参数错误问题

#### 问题1: `top_n` 错误（14次，最严重）

**错误模式统计**：
- 目标10但预测5：**12次**（占85.7%）
- 目标5但预测10：1次
- 目标10但预测8：1次

**示例**：
```
查询: "2025年第二季度，雷迪森酒店客户下单金额最高的订单有哪些？"
目标: top_n = 10  (查询中未明确指定数量，使用默认值10)
预测: top_n = 5   (模型默认使用5)

查询: "2025年7月15日到9月12日，景澜酒店客户下单最少的是那些？"
目标: top_n = 5   (查询中提到"那些"，暗示少量)
预测: top_n = 10  (模型使用了默认值10)
```

**根因分析**：
1. **默认值理解问题**：模型不知道`top_n`的默认值应该是10，倾向于使用5
2. **数量推断问题**：当查询中未明确指定数量时，模型无法正确推断应该使用默认值10
3. **语义理解问题**：查询中"那些"、"哪些"等词可能暗示不同数量，但模型理解不一致

#### 问题2: `time_filter` 错误（2次）

**错误模式**：
1. **日期范围错误**：预测的结束日期超出目标范围
2. **日期格式错误**：预测使用简化格式（如"2025-6-1"）而非标准格式（"2025-06-01"）

**示例**：
```
查询: "请查一下2025年8月订单数量最多的客户，并展示他们的详细信息。"
目标: {"start_date": "2025-08-01", "end_date": "2025-08-31"}
预测: {"start_date": "2025-08-01", "end_date": "2025-10-17"}  (结束日期错误)

查询: "从25年6月1日到8月1日，哪些产品的收入最高？"
目标: {"start_date": "2025-06-01", "end_date": "2025-08-01"}
预测: {"start_date": "2025-6-1", "end_date": "2025-8-1"}  (格式错误)
```

**根因**：
1. **日期解析问题**：模型可能使用了当前日期或其他日期作为结束日期
2. **格式标准化问题**：模型没有统一使用YYYY-MM-DD格式

#### 问题3: `entity_type` 错误（1次）

**错误模式**：
- 目标：`customer`
- 预测：`order`

**示例**：
```
查询: "2025年第二季度，雷迪森酒店客户下单金额最高的订单有哪些？"
目标: entity_type = "customer"  (查询中提到"客户")
预测: entity_type = "order"     (查询中也提到"订单"，模型选择了错误的实体)
```

**根因**：
- 查询中同时提到"客户"和"订单"，模型混淆了应该提取哪个实体类型
- 需要理解查询的主语：查询的是"客户"的订单金额，所以应该是`customer`

#### 问题4: `ranking_type` 错误（1次）

**错误模式**：
- 目标：`lowest_amount`
- 预测：`lowest_revenue`

**示例**：
```
查询: "2025年7月17日到9月12日客户订单收入最低的前5个客户有哪些"
目标: ranking_type = "lowest_amount"  (订单金额)
预测: ranking_type = "lowest_revenue"  (收入，但工具可能不支持此类型)
```

**根因**：
- 查询中提到"收入"，但工具可能只支持`lowest_amount`（订单金额）
- 模型混淆了"收入"和"金额"的概念

#### 问题5: `resort_filter` 错误（1次）

**错误模式**：
- 目标：`"雷迪森酒店"`
- 预测：`"雷迪森"`

**示例**：
```
查询: "2025年8月1日到10月22日，雷迪森酒店的订单金额最高的是哪些"
目标: resort_filter = "雷迪森酒店"
预测: resort_filter = "雷迪森"
```

**根因**：
- 实体名称提取不完整，缺少"酒店"后缀
- 可能是NER模型或实体匹配问题

#### 问题6: `include_details` 错误（1次）

**错误模式**：
- 目标：`False`
- 预测：`True`

**示例**：
```
查询: "2025年第二季度，景澜酒店的订单收入最高的是哪些客户"
目标: include_details = False
预测: include_details = True
```

**根因**：
- 查询中提到"哪些客户"，模型可能认为需要详情
- 但实际目标是不需要详情，可能是业务逻辑或训练数据标注问题

## 三、共性问题总结

### 3.1 隐式参数推断问题

1. **默认值参数缺失**：
   - `include_details`: 查询中未明确提到时，需要推断默认值（通常是False）
   - `top_n`: 查询中未明确指定数量时，需要推断默认值（通常是10）

2. **实体类型推断**：
   - `entity_type`: 需要从查询语义推断是查询"客户"还是"订单"
   - 当查询中同时提到多个实体时，需要理解查询的主语

### 3.2 数值提取和标准化问题

1. **数量提取**：
   - `top_n`: 需要从"前10"、"前5"、"那些"等表达中提取数量
   - 当未明确指定时，需要理解默认值规则

2. **日期格式标准化**：
   - `time_filter`: 需要统一使用YYYY-MM-DD格式
   - 需要正确解析"25年"、"6月1日"等非标准日期表达

### 3.3 实体识别问题

1. **实体名称完整性**：
   - `resort_filter`: 需要提取完整的景区名称（如"雷迪森酒店"而非"雷迪森"）

2. **实体类型识别**：
   - 需要区分"客户"、"订单"、"产品"等不同实体类型

### 3.4 语义理解问题

1. **同义词/近义词混淆**：
   - `ranking_type`: "收入" vs "金额"的混淆
   - `entity_type`: "客户下单" vs "订单"的混淆

2. **查询意图理解**：
   - 需要理解查询的真正意图，而非仅依赖关键词匹配

## 六、具体实施建议

1. **修改现有训练样本（30-40%）**：
   - 在查询中自然融入参数提示
   - 保持目标参数不变

   - 展示默认值参数的使用规则

   - 提供参数使用示例

## 七、总结

`rank_orders`工具的主要问题集中在：

1. **默认值参数推断**：`top_n`和`include_details`的默认值使用
2. **实体类型识别**：`entity_type`的提取和推断
3. **数值提取和标准化**：数量、日期的提取和格式标准化
4. **实体名称完整性**：景区名称的完整提取

建议采用**策略5（数量推断）+ 策略1（显式提示）+ 策略7（few-shot示例）**的组合方式，重点解决`top_n`和`include_details`的问题。
