# 为什么 customer 样本有33个，但模型还是没有学会提取？

## 一、关键发现

### 1.1 训练数据实际情况

从训练数据分析发现：

**训练数据中 `entity_type = "customer"` 的样本**：
- 总样本数：33个
- **查询中包含"客户"关键词的样本**：**0个（0%）** ⚠️
- **查询中不包含"客户"关键词的样本**：**33个（100%）** ⚠️

**但实际查看训练数据文件发现**：
- 有些样本确实在查询中提到了"客户"，比如：
  - "我想问问，2025年8月订单数量最少的客户是哪家？" → `entity_type = "customer"`
  - "请查一下2025年8月订单数量最多的客户，并展示他们的详细信息。" → `entity_type = "customer"`
  - "今年上半年订单数量最多的前10位客户是哪些？" → `entity_type = "customer"`

### 1.2 测试集失败案例

**测试集中 `entity_type = "customer"` 缺失的案例**：
```
查询: "想了解下2025年第二季度哪些客户的订单数量最少，前五名就行。"
目标: entity_type = "customer"
预测: entity_type = null
查询中的关键词: 客户, 哪些客户  ← 明确提到了"客户"
```

---

## 二、问题根因分析

### 2.1 训练数据标注不一致问题

**问题1：部分样本查询中没有明确提到"客户"**

虽然训练数据中有33个 `entity_type = "customer"` 的样本，但可能：
- **部分样本的查询中没有明确提到"客户"关键词**
- 模型可能通过其他方式（如 `ranking_type`、上下文等）推断出 `entity_type = "customer"`
- 但**没有学会从"客户"关键词直接提取**

**示例**：
```
查询: "2025年8月订单数量最多的"  (没有提到"客户")
entity_type: "customer"  (通过其他方式推断)
```

**问题2：模型学会了错误的推断模式**

模型可能学会了：
- 通过 `ranking_type = "most_orders"` + 某些上下文 → `entity_type = "customer"`
- 通过其他模式推断，而不是从"客户"关键词提取

但当测试集中出现新的查询表达时，如果不符合训练数据中的模式，模型就无法提取。

### 2.2 关键词到参数的映射未建立

**核心问题**：
- 训练数据中虽然标注了 `entity_type = "customer"`
- 但**模型没有建立"客户"关键词 → `entity_type = "customer"` 的直接映射关系**
- 模型可能认为：`entity_type` 是通过其他方式推断的，而不是从查询中的关键词提取的

### 2.3 样本质量问题

**可能的问题**：
1. **样本表达方式单一**：
   - 训练数据中的查询表达方式可能比较单一
   - 测试集中的查询表达方式可能不同
   - 模型没有学会泛化

2. **样本中关键词位置不固定**：
   - 训练数据中"客户"可能出现在不同位置
   - 模型没有学会识别不同位置的"客户"关键词

3. **样本中同时提到多个实体**：
   - 有些查询可能同时提到"客户"和"订单"
   - 模型可能混淆应该提取哪个实体类型

### 2.4 默认值理解偏差

**问题**：
- 工具schema中 `entity_type` 的默认值是 `"order"`
- 训练数据中即使目标是 `customer`，也显式标注了 `entity_type: "customer"`
- 但模型可能认为：
  - 只有当目标是 `customer` 或 `product`（非默认值）时才需要提取
  - 当目标是 `order`（默认值）时不需要提取
  - **但没有学会：当查询中提到"客户"时，应该提取 `entity_type: "customer"`**

---

## 三、深层原因分析

### 3.1 模型学习的是"模式匹配"而非"关键词提取"

**模型可能学会了**：
- 某些查询模式 → `entity_type = "customer"`
- 某些 `ranking_type` + 上下文 → `entity_type = "customer"`

**模型没有学会**：
- "客户"关键词 → `entity_type = "customer"` 的直接映射
- 从查询语义推断 `entity_type`

### 3.2 训练数据中缺少明确的"关键词-参数"对应关系

**问题**：
- 训练数据中虽然标注了 `entity_type = "customer"`
- 但查询中可能没有明确提到"客户"，或者提到的方式不够明显
- 模型没有看到"客户"关键词与 `entity_type = "customer"` 的明确对应关系

### 3.3 样本分布问题

**可能的问题**：
- 虽然 `customer` 样本有33个，但可能：
  - 查询表达方式相似（缺乏多样性）
  - 查询中没有明确提到"客户"关键词
  - 模型学会了错误的推断模式

---

## 四、解决方案

### 策略1：增加明确包含"客户"关键词的训练样本（最紧急）

**问题**：训练数据中可能缺少明确提到"客户"的样本

**解决方案**：
1. **确保所有 `entity_type = "customer"` 的样本，查询中都明确提到"客户"**
2. **增加各种表达方式的样本**：
   - "哪些客户"
   - "客户订单"
   - "客户下单"
   - "客户数量"
   - "客户收入"

**示例**：
```json
{
  "conversations": [
    {
      "from": "human",
      "value": "想了解下2025年第二季度哪些客户的订单数量最少，前五名就行"
    },
    {
      "from": "function_call",
      "value": "{\"name\": \"rank_orders\", \"arguments\": {\"ranking_type\": \"least_orders\", \"top_n\": 5, \"time_filter\": {\"start_date\": \"2025-04-01\", \"end_date\": \"2025-06-30\"}, \"entity_type\": \"customer\"}}"
    }
  ]
}
```

### 策略2：增加few-shot示例，明确关键词映射规则

**在训练数据开头增加few-shot示例**：

```json
{
  "conversations": [
    {
      "from": "system",
      "value": "rank_orders工具的entity_type参数提取规则：\n1. 当查询中提到'客户'、'哪些客户'、'客户订单'、'客户下单'等时，必须提取entity_type='customer'\n2. 当查询中提到'订单'、'订单金额'、'订单数量'等时，必须提取entity_type='order'\n3. 当查询中提到'产品'、'哪些产品'等时，必须提取entity_type='product'\n4. 即使entity_type有默认值，当查询中明确提到相关关键词时，仍必须显式提取该参数"
    },
    {
      "from": "human",
      "value": "想了解下2025年第二季度哪些客户的订单数量最少，前五名就行"
    },
    {
      "from": "function_call",
      "value": "{\"name\": \"rank_orders\", \"arguments\": {\"ranking_type\": \"least_orders\", \"top_n\": 5, \"time_filter\": {\"start_date\": \"2025-04-01\", \"end_date\": \"2025-06-30\"}, \"entity_type\": \"customer\"}}"
    }
  ]
}
```

### 策略3：修改现有训练样本，确保查询中包含关键词

**检查并修改现有训练样本**：
- 如果查询中没有明确提到"客户"，但标注了 `entity_type = "customer"`，需要：
  1. 修改查询，明确提到"客户"
  2. 或者删除该样本（如果无法修改）

**示例调整**：

**原样本**（可能的问题样本）：
```
查询: "2025年8月订单数量最多的"  (没有提到"客户")
entity_type: "customer"
```

**调整后**：
```
查询: "2025年8月订单数量最多的客户是哪些"  (明确提到"客户")
entity_type: "customer"
```

### 策略4：增加负样本训练

**增加一些样本，明确说明何时不应该提取 `entity_type`**：

```json
{
  "conversations": [
    {
      "from": "human",
      "value": "2025年8月的订单统计情况"  // 没有明确提到实体类型
    },
    {
      "from": "function_call",
      "value": "{\"name\": \"rank_orders\", \"arguments\": {\"ranking_type\": \"most_orders\", \"time_filter\": {\"start_date\": \"2025-08-01\", \"end_date\": \"2025-08-31\"}}}"
      // 不包含 entity_type，使用默认值 "order"
    }
  ]
}
```

### 策略5：增强工具schema描述

**修改工具schema中 `entity_type` 参数的描述**：

```json
{
  "entity_type": {
    "type": "string",
    "description": "实体类型。**必须从查询中提取**：当查询中提到'客户'、'哪些客户'、'客户订单'、'客户下单'等关键词时，必须提取'customer'；当查询中提到'订单'、'订单金额'、'订单数量'等关键词时，必须提取'order'；当查询中提到'产品'、'哪些产品'等关键词时，必须提取'product'。即使默认值是'order'，当查询中明确提到相关关键词时，仍必须显式提取该参数。",
    "default": "order",
    "enum": ["order", "customer", "product"]
  }
}
```

## 五、优先级建议

### 优先级1（最紧急）：策略1 + 策略3
- **检查所有 `entity_type = "customer"` 的训练样本**
- **确保查询中都明确提到"客户"关键词**
- **如果查询中没有提到，修改查询或删除样本**

### 优先级2：策略2
- **增加few-shot示例**，明确关键词映射规则
- **帮助模型建立"客户"关键词 → `entity_type = "customer"` 的直接映射**

### 优先级3：策略5
- **增强工具schema描述**，明确参数提取规则
- **在推理时提供更好的指导**

## 六、总结

### 核心问题
1. **训练数据中虽然标注了 `entity_type = "customer"`，但可能部分样本的查询中没有明确提到"客户"关键词**
2. **模型学会了通过其他方式（如 `ranking_type`、上下文）推断 `entity_type`，但没有学会从"客户"关键词直接提取**
3. **模型没有建立"客户"关键词 → `entity_type = "customer"` 的直接映射关系**

### 解决方案
1. **确保所有 `entity_type = "customer"` 的样本，查询中都明确提到"客户"**
2. **增加few-shot示例，明确关键词映射规则**
3. **修改现有训练样本，确保查询中包含关键词**
4. **增强工具schema描述，明确参数提取规则**

### 关键点
- **样本数量多不等于样本质量好**
- **模型需要看到明确的"关键词-参数"对应关系才能学会提取**
- **即使有33个样本，如果样本质量不好（查询中没有明确提到关键词），模型仍然学不会**
