## 🎯 根本原因分析

### 核心问题：**分布不匹配（Distribution Mismatch）**

查看 `data_evaluation_singlehop.py` 的代码（1019-1035行）：

```python
# 如果有实际检索结果，重新构建prompt
if actual_observation and used_actual_retrieval:
    # 替换user_prompt中的observation
    # 使用实际检索返回的结果
    actual_observation = self.retrieval_caller.build_observation_from_response(retrieval_response)
    new_user_prompt = re.sub(pattern, f"工具返回: {obs_preview}", ex.user_prompt, ...)
else:
    # 使用训练数据中的observation
    logger.info("业务跳 Pair {} 使用训练数据中的observation")
```

### 问题所在

**训练时**：
- 模型看到的是**训练数据中的observation**（固定的、训练时见过的数据）

**评估时**（当前逻辑）：
- 如果检索成功：使用**实际检索返回的结果**（动态的、可能不同的数据）
- 如果检索失败：使用训练数据中的observation

**结果**：
- 训练时和评估时看到的observation**不一致**
- 模型在训练时学习的模式，在评估时可能不适用
- 这就是为什么即使过拟合，业务工具指标也不理想

## 📊 可能的原因列表

### 1. **分布不匹配（最可能）** ⭐⭐⭐⭐⭐

**现象**：
- 训练时：看到训练数据中的observation
- 评估时：看到实际检索返回的observation（可能格式、内容不同）

**影响**：
- 即使模型完全记忆了训练数据，评估时看到的输入不同，输出也会不同
- 这是业务工具Accuracy低的主要原因

**证据**：
- 检索工具Accuracy高（0.976）：因为输入格式一致
- 业务工具Accuracy低（0.542）：因为输入（observation）不一致

### 2. **实际检索结果与训练数据差异**

**可能差异**：
- **格式差异**：JSON结构、字段顺序、嵌套层级
- **内容差异**：工具列表顺序、工具描述、字段值
- **完整性差异**：返回的工具数量、字段完整性

**影响**：
- 模型期望看到训练数据中的格式，但实际看到不同的格式
- 导致参数提取错误

### 3. **检索服务返回结果不稳定**

**可能问题**：
- 检索服务在不同时间返回不同的结果
- 即使query相同，返回的工具列表可能不同
- 导致评估结果不稳定

### 4. **训练数据质量问题**

**可能问题**：
- 训练数据中的observation格式不统一
- 训练数据中的参数格式与评估时不一致
- 训练数据中的工具列表与评估时不同

### 5. **参数匹配的严格性**

**严格模式要求**：
- 参数值必须**完全匹配**
- 格式、类型、顺序都必须一致
- 即使微小的差异也会导致失败

**影响**：
- 即使模型学会了参数提取，格式差异也会导致匹配失败

## ⚠️ 注意事项

### 1. 评估场景的区分

**使用训练数据observation**：
- ✅ 适合：评估模型的**训练集表现**（过拟合测试）
- ✅ 适合：评估模型的**记忆能力**
- ❌ 不适合：评估模型的**泛化能力**

**使用实际检索结果**：
- ✅ 适合：评估模型的**真实应用表现**
- ✅ 适合：评估模型的**泛化能力**
- ❌ 不适合：评估过拟合程度

### 2. 两种评估方式的意义

**方式1：使用训练数据observation**
- 目的：测试模型对训练数据的记忆程度
- 结果：应该接近1.0（如果充分过拟合）
- 意义：验证过拟合配置是否生效

**方式2：使用实际检索结果**
- 目的：测试模型在真实场景的表现
- 结果：可能较低（因为分布不匹配）
- 意义：评估实际应用能力

### 3. 建议的评估策略

**阶段1：使用训练数据observation**
- 验证过拟合配置是否生效
- 如果Accuracy达到0.85+，说明过拟合成功
- 如果Accuracy仍然低，说明有其他问题

**阶段2：使用实际检索结果**
- 评估真实应用能力
- 如果Accuracy仍然低，需要改进模型或数据
