# LLaMA-Factory 回调函数工作流程说明

## 概述

在您的 `callbacks.py` 文件中，定义了多个回调类（Callback Classes），这些回调通过继承 `TrainerCallback` 基类，在训练的不同阶段被自动调用。以下是这些"tag"（钩子方法）如何在整个训练流程中工作的详细说明。

## 一、回调注册流程

### 1. 入口点（`tuner.py`）

```python
# 文件位置: src/llamafactory/train/tuner.py

def _training_function(config: dict[str, Any]) -> None:
    callbacks = config.get("callbacks")  # 获取回调列表
    
    # 按顺序添加各种回调
    callbacks.append(LogCallback())                      # 日志回调
    callbacks.append(PissaConvertCallback())             # PiSSA转换回调（如果需要）
    callbacks.append(get_swanlab_callback())             # SwanLab回调（如果需要）
    callbacks.append(EarlyStoppingCallback())            # 早停回调（如果需要）
    callbacks.append(ReporterCallback(...))              # 外部报告回调
    
    # 根据训练阶段调用不同的训练函数
    if finetuning_args.stage == "sft":
        run_sft(..., callbacks)  # 将回调传递给SFT训练函数
```

### 2. 训练器初始化（`sft/trainer.py`）

```python
# 文件位置: src/llamafactory/train/sft/trainer.py

class CustomSeq2SeqTrainer(Seq2SeqTrainer):
    def __init__(self, ...):
        super().__init__(**kwargs)
        
        # 添加处理器保存回调
        if processor is not None:
            self.add_callback(SaveProcessorCallback(processor))
        
        # 添加标签预测监控回调（您添加的自定义回调）
        from ..callbacks import LabelPredictionMonitorCallback
        monitor_callback = LabelPredictionMonitorCallback(
            output_dir=self.args.output_dir,
            log_interval=5,
            save_detailed_logs=True
        )
        self.add_callback(monitor_callback)  # 注册到训练器
        
        # 设置tokenizer到监控回调
        if hasattr(self, 'tokenizer'):
            monitor_callback.set_tokenizer(self.tokenizer)
```

## 二、训练流程中的回调执行顺序

以下是 Transformers Trainer 在训练过程中按时间顺序调用的钩子方法：

### 1. 初始化阶段

```
Trainer.__init__()
  ↓
on_init_end()  # 训练器初始化完成
```

**在 callbacks.py 中的使用：**
- `LogCallback.on_init_end()`: 检查并删除旧的训练日志文件

### 2. 训练开始阶段

```
Trainer.train()
  ↓
on_train_begin()  # 训练开始前
```

**在 callbacks.py 中的使用：**
- `LogCallback.on_train_begin()`: 初始化计时器和线程池
- `PissaConvertCallback.on_train_begin()`: 保存初始PiSSA adapter
- `ReporterCallback.on_train_begin()`: 向wandb/swanlab上传配置
- `LabelPredictionMonitorCallback`: 您的自定义回调可以在这里做初始化

### 3. 训练循环（每个epoch）

```
for epoch in range(num_epochs):
    ↓
    on_epoch_begin()  # epoch开始
    ↓
    for step in range(steps_per_epoch):
        ↓
        compute_loss()  # 计算损失（这里可以插入自定义逻辑）
        ↓
        on_substep_end()  # 子步骤结束（gradient accumulation）
        ↓
        on_step_end()    # 完整训练步骤结束
        ↓
        [每N步] on_save()     # 保存检查点
        [每N步] on_log()      # 记录日志
        [每N步] on_evaluate() # 运行评估
    ↓
    on_epoch_end()  # epoch结束
```

**在 callbacks.py 中的使用：**

#### `on_step_end()` - 每个训练步骤后调用
```python
# LabelPredictionMonitorCallback 中
def on_step_end(self, args, state, control, **kwargs):
    self.step_count += 1
    if self.step_count % self.log_interval == 0:
        # 记录训练状态
        self.loggers["labels"].info(f"🔄 训练步骤 {state.global_step} 监控")
```

#### `on_log()` - 记录日志时调用
```python
# LogCallback 中
def on_log(self, args, state, control, **kwargs):
    logs = dict(
        current_steps=self.cur_steps,
        loss=state.log_history[-1].get("loss"),
        lr=state.log_history[-1].get("learning_rate"),
        ...
    )
    self.thread_pool.submit(self._write_log, args.output_dir, logs)
```

#### `on_save()` - 保存模型时调用
```python
# FixValueHeadModelCallback 中
def on_save(self, args, state, control, **kwargs):
    if args.should_save:
        output_dir = os.path.join(args.output_dir, f"checkpoint-{state.global_step}")
        fix_valuehead_checkpoint(model, output_dir, ...)
```

#### `on_evaluate()` - 评估时调用
```python
# LabelPredictionMonitorCallback 中
def on_evaluate(self, args, state, control, **kwargs):
    self.loggers["predictions"].info(f"📊 评估阶段监控 - 步骤 {state.global_step}")
    if 'predict_results' in kwargs:
        self._analyze_predictions(kwargs['predict_results'], state.global_step)
```

### 4. 训练结束阶段

```
Training completed
  ↓
on_train_end()  # 训练结束
```

**在 callbacks.py 中的使用：**
- `LogCallback.on_train_end()`: 关闭线程池
- `PissaConvertCallback.on_train_end()`: 转换并保存PiSSA adapter
- `LabelPredictionMonitorCallback.on_train_end()`: 保存最终的训练摘要

### 5. 预测阶段（如果有）

```
on_prediction_step()  # 每个预测步骤
  ↓
on_predict()  # 预测结束
```

## 三、自定义回调的特殊调用点

### 在 `compute_loss()` 中的手动调用

您的 `LabelPredictionMonitorCallback` 还有两个特殊的方法，它们不是标准的回调钩子，而是在 `compute_loss()` 中手动调用的：

```python
# 文件位置: src/llamafactory/train/sft/trainer.py

def compute_loss(self, model, inputs, *args, **kwargs):
    # 遍历所有回调，找到有特定方法的回调并调用
    for callback in self.callback_handler.callbacks:
        # 1. 分析训练Token
        if hasattr(callback, 'analyze_training_tokens'):
            labels = inputs.get('labels')
            if labels is not None:
                callback.analyze_training_tokens(model, inputs, labels)
        
        # 2. 分析模型预测
        if hasattr(callback, 'analyze_model_predictions'):
            labels = inputs.get('labels')
            if labels is not None:
                callback.analyze_model_predictions(model, inputs, labels)
    
    # 调用父类的compute_loss计算实际损失
    return super().compute_loss(model, inputs, *args, **kwargs)
```

这意味着**每次前向传播计算损失时**，您的监控方法都会被调用。

   - 完整的训练历史
   - 预测历史

## 六、关键标签（Tag）说明

您在代码中使用的 `@override` 装饰器标记的方法，就是训练器在不同阶段会自动调用的"tag"：

| 标签方法 | 调用时机 | 在您的回调中的作用 |
|---------|---------|-------------------|
| `on_init_end` | 训练器初始化后 | （未使用） |
| `on_train_begin` | 训练开始前 | （未使用，但可用于初始化） |
| `on_epoch_begin` | 每个epoch开始 | （未使用） |
| `on_step_end` | 每个训练步骤后 | ✅ 更新步骤计数，记录训练状态 |
| `on_substep_end` | gradient accumulation子步骤后 | （未使用） |
| `on_log` | 日志记录时 | ✅ 获取训练日志信息 |
| `on_save` | 保存检查点时 | （未使用） |
| `on_evaluate` | 评估时 | ✅ 分析评估结果 |
| `on_predict` | 预测时 | ✅ 分析预测结果 |
| `on_prediction_step` | 每个预测步骤 | （未使用） |
| `on_train_end` | 训练结束时 | ✅ 保存最终摘要 |
| `on_epoch_end` | 每个epoch结束 | （未使用） |

## 七、执行频率控制

您在代码中使用 `log_interval` 参数来控制详细日志的记录频率：

```python
# 只在特定步骤记录详细信息
if self.step_count % self.log_interval == 0:
    self.loggers["labels"].info(f"🔍 训练Token分析 - 步骤 {self.step_count}")
    # ... 详细分析代码
```

这样可以避免日志文件过大，同时保持必要的监控信息。

## 八、总结

您的回调系统通过以下方式工作：

1. **注册**: 在 `CustomSeq2SeqTrainer.__init__()` 中通过 `self.add_callback()` 注册
2. **自动调用**: Transformers 训练器在特定阶段自动调用 `@override` 标记的方法
3. **手动调用**: 在 `compute_loss()` 中手动调用自定义方法进行深度监控
4. **日志记录**: 通过多个日志文件分类记录不同类型的信息
5. **频率控制**: 使用 `log_interval` 控制详细日志的记录频率

这种设计使得您可以在不修改训练主逻辑的情况下，深入监控训练过程中的各种细节。
